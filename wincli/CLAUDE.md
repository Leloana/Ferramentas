# WINCLI — Developer Guide

WINCLI is a terminal-based agentic CLI for Windows that connects to a local Ollama instance.
The user types requests in natural language; the agent uses tools to read, write, and run commands.

---

## Running

```powershell
# First-time setup
.\setup.bat

# Launch
.\run.bat
```

Or directly:
```powershell
.venv\Scripts\python.exe main.py
```

Requires Ollama running locally with at least one model pulled.

---

## Project Structure

```
main.py          — entry point, REPL loop, slash commands
agent.py         — core agent loop (stream → parse → gate → execute → log)
subagent.py      — isolated sub-agent used by skills (plan, etc.)
modes.py         — op/perm mode state, permission gate, tool previews
tools.py         — core tool implementations (read, write, patch, run, remove, list, search, http)
ui.py            — all terminal output: console, select menus, panels, banner
persist.py       — session logging and resume
snapshot.py      — file snapshots for /undo
init_skill.py    — /init: generates WINCLI.md from the current project
plan_skill.py    — legacy single-agent planner (unused by default)

skills/
  __init__.py    — skill registry and loader
  plan.py        — multi-agent planner (planner → reviewer → executors → verifier)
  debug.py       — /debug skill
  reflect.py     — /reflect skill (triggered by circuit breaker)
  add_skill.py   — /add_skill: scaffold a new skill file
  add_tool.py    — /add_tool: scaffold a new tool in extra_tools.py

.persist/        — session JSON files and input history (gitignored)
plans/           — markdown plan files generated by /plan
```

## Key Concepts

**Tools** — the agent communicates via JSON tool calls inside markdown fences:
```json
{"tool": "read_file", "args": {"path": "C:\\absolute\\path\\to\\file"}}
```
All paths must be absolute. Tools: `read_file`, `write_file`, `patch_file`, `remove_file`,
`list_dir`, `search_file`, `run_command`, `http_get`.

**Context** — the conversation history grows in-memory during a session. Use `/clear` to
reset it when VRAM pressure builds up (common after long sessions or `/plan` runs).
`/clear` wipes only the in-memory messages — the session log in `.persist/` is preserved.

**Modes** — two orthogonal axes controlled via `/mode`:
- `op_mode`: `normal` | `plan` | `debug`
- `perm_mode`: `bypass` | `ask_edits` (default) | `ask_all`

`ask_edits` gates only mutating tools (write, patch, remove, run_command).

**Skills** — invoked via `/skill <name>` or sugar commands (`/plan`, `/debug`, `/reflect`).
Each skill is a Python module in `skills/` with `NAME`, `DESCRIPTION`, and `run(args, ctx)`.

**SubAgent** — isolated model session used by the plan skill for each role (planner, reviewer,
executor, verifier). Has its own context, system prompt, and tool whitelist.

## Coding Guidelines

- **Shell is PowerShell** — all `run_command` calls use PowerShell syntax (`Get-ChildItem`, not `ls`).
- **Colors**: red for errors/failures, green for success, yellow for warnings. Plain white otherwise.
- **UI**: all choices go through `ui.select()` — no typed single-key shortcuts.
- **No relative paths** — always resolve to absolute paths via `tools._resolve_abs()`.
- **Mutating tools** require explicit user confirmation unless `perm_mode` is `bypass`.
- **Before patching or removing a file**, the agent must call `list_dir` on the parent directory first.
- **Session state** lives in `.persist/` — do not delete it manually between runs if you want resume.

## Adding a Skill

```powershell
# Inside the CLI:
/skill add_skill my_skill_name
```

Or manually create `skills/my_skill.py`:
```python
NAME = "my_skill"
DESCRIPTION = "One-line description shown in /skills"

def run(args: str, ctx: dict) -> dict:
    # ctx keys: working_dir, model, wincli_content, conversation_history,
    #           session_log, state, snapshot_mgr
    ...
    return {"status": "ok"}
```

## Adding a Tool

```powershell
/skill add_tool my_tool_name
```

Or add a function to `extra_tools.py` (created automatically). Register in `tools.CORE_TOOLS`
if it should be permanent. Add to `modes.MUTATING_TOOLS` if it modifies files or state.
